# 验证记录

本文件记录真实站点的实测结果，以及**哪些结论有证据、哪些还没有**。
模拟测试通过不等于站点可用，未验证的部分单独列出。

## 2026-10-15：首次真实采集（搜索条件 social + active + q=agent）

### 环境与条件

| 项 | 值 |
| --- | --- |
| 运行时间 | 2026-10-15 19:10 ~ 19:40（+08:00） |
| 站点 | `https://jobs.ultraai.site` |
| 搜索条件 | `job_type=social`、`status=active`、`q=agent` |
| 窗口字段 | `first_seen_at`（站点显示的「收录时间」） |
| 窗口 | 最近 30 天：`2026-09-15T19:10:30+08:00` ～ `2026-10-15T19:10:30+08:00` |
| 批次 | `20261015-1910-agent` |
| 运行方式 | Python 3.12（Anaconda），仅标准库；无浏览器、无登录 |
| 请求量 | 列表 80 次 + 详情 635 次，串行，间隔 400／700 毫秒 |

### 1. 列表阶段

| 观察项 | 结果 |
| --- | --- |
| 站点报告 `total` | 4779 |
| 站点报告 `pages` × `page_size` | 80 × 60 |
| 实际读取页数 | 80（全部） |
| 实际取得记录数 | 4779 |
| 主键重复数 | 0 |
| 翻页期间 `total` 是否变化 | 未变化（4779 → 4779） |
| 达到预算上限 | 否（`maxPages=200`、`maxJobs=6000` 均未触及） |
| 窗口内 | 635 |
| 窗口外 | 4144，全部为 `before_window` |

**窗口判定独立重算**：不信任入库时的标记，直接用原始 `first_seen_at` 与窗口边界重算全部
4779 条，结果 635 条在窗口内，与入库标记 **0 处不一致**；`first_seen_at` 缺失的记录 0 条。

**为什么必须读完全部 80 页**：实测列表顺序**不**等价于收录时间倒序。
在首次（被 `maxJobs=2000` 截断的）试跑中，前 2000 条里只得到 613 条窗口内记录；
放开上限读完 4779 条后为 635 条，**那次截断静默漏掉了 22 条**。
进一步核对：窗口内记录出现在列表第 4773 位，而窗口外记录出现在第 91 位。
因此任何「读到旧记录就提前停止」的优化都会漏数据，程序不会这样做。

**可复现性**：约 45 分钟后用固定 `--as-of 2026-10-15T19:10:30+08:00` 重跑同一批次，
再次得到 4779 条、0 重复、635 条窗口内，与首次一致。

### 1b. `q` 命中的是标题或岗位详情（重要）

用户反馈「标题里没有 agent 的岗位为什么会被搜出来」，核对结论：**站点的搜索行为如此，不是采集错误**。

站点搜索页写明「标题命中优先，其次匹配岗位详情」，`q` 返回的是两者的并集。
`query_score` 是机器可读的命中位置标记，实测只有三档，且与「标题是否含关键词」完全对应：

| `query_score` | 条数 | 标题含 `agent` |
| --- | --- | --- |
| 110 | 964 | 是 |
| 100 | 37 | 是 |
| 10 | 3778 | 否 |

- 标题含 `agent` 的 1001 条 = 964 + 37，`query_score` 只取 110 与 100；
- 标题不含的 3778 条，`query_score` 全部为 10；
- 逐条核对，**两个方向都没有例外**。

窗口内 635 条的分布：

| 口径 | 条数 |
| --- | --- |
| 站点返回的全部窗口内结果 | 635 |
| 标题命中 `agent` | **104** |
| 仅靠岗位详情命中 | 531 |

用户估计的「100 多条」正好等于 **104** 这个标题命中的子集。
只在详情里命中的 531 条中，529 条正文确实含 `agent`（匹配是真的，不是模糊召回），
但多数只是要求里顺带一句「有 Agent 设计和实现经验者优先」——
用户点名的 `xiaomi/7696728516373793066`「Java研发专家」即属此类，
其正文第 7 条写着「有 Agent 设计和实现经验者优先，有 AICoding 背景下复杂系统设计或重构经验者优先」。
窗口内只有 2 条既不在标题、也不在已采集正文中出现 `agent`
（`netease/41029`、`jd/175923`），可能命中站点掌握但页面区块之外的文本，未进一步追查。

站点 UI 既不使用 `query_score` 也不做筛选，页面计数显示完整 `total`（4,780），
因此只浏览前几页会看到清一色标题命中结果，容易误判结果集规模。

处理方式：导出同时给出 `jobs.csv`（635）与 `jobs-title-hit.csv`（104）两种口径，
`query_score`、`match_scope` 两列也写入 CSV，换口径不需要重新采集。

### 2. 详情阶段

| 观察项 | 结果 |
| --- | --- |
| 待抓取 | 635 |
| 成功取得完整 JD（`ok`） | 635（100%） |
| 其它状态（`incomplete`/`mismatch`/`unverified`/`missing`/`error`） | 0 |
| 解析路径 | `json-ld` 508、`html` 127 |
| 标题与列表一致性 | 635/635 一致（`title_matches=1`） |
| 覆盖招聘来源 | 30 个（腾讯 88、字节 74、美团 68、阿里云 57、蚂蚁 57、百度 36、网易 31 …） |

| JD 字数 < 100 的条数 | 0 |
| 单条请求耗时 中位数／p90／最大 | 2125 / 2954 / 4438 毫秒 |

**解析路径说明**：`html` 路径的 127 条不是失败，而是这些详情页没有
`application/ld+json` 的 `JobPosting`（例如美团来源），程序按 `dossier-section`
正文区块解析成功。这条回退路径是必需的，不是冗余实现。

### 3. 抽查与核对

下面这些检查由 `tools/spot_check.py` 执行，可随时复现（B、C 离线，D 需 `--live`）：

| 检查 | 方法与结果 |
| --- | --- |
| 反伪造（离线，635 条全覆盖） | 入库的职责／要求文本，去标签去空白后必须出现在该岗位**归档的原始 HTML** 里（正文区块 + JSON-LD 全部字符串）。**635/635 通过，0 条无法溯源** |
| 完整 JD vs 列表摘要（635 条全覆盖） | 入库 JD 字数大于列表接口 `description_excerpt` 字数的：**635/635**。摘要没有被当成完整正文 |
| 实时复核（随机抽 5 条） | 重新访问站点并重新解析，与库中内容逐字比较：**5/5 完全一致**（字节跳动、哔哩哔哩、美团、淘天、阿里各 1 条） |
| 收录时间口径抽查（8 个不同来源） | 详情页 `<time datetime>` 与列表接口 `first_seen_at` 逐条一致 |
| 短 JD 人工查看 | 最短 4 条（151／194／257／261 字）逐条阅读：内容完整、属于岗位本身确实简短，**不是截断** |

**注意一处检查方法的坑**：最初的「反伪造」检查只比对页面可见正文，于是 832 项报错——
因为 508 条走的是 JSON-LD 路径，而那段文本在 `<script>` 里，去脚本后自然找不到。
这是检查方法的漏洞，不是数据问题；把 JSON-LD 的字符串一并纳入证据集合后为 0 报错。
记录在此以免下次重复踩坑。

## 2026-10-15：`batches --limit`（纯离线，不访问站点）

本地批次积累后需要只看最近 N 条，因此为 `batches` 增加可选 `--limit N`。

| 项 | 值 |
| --- | --- |
| 数据来源 | 全部为虚构批次，写入临时目录下的本地 SQLite；**不访问采集站点、无任何真实数据或账号** |
| 存储层 | 限制在 SQL 查询中完成（`LIMIT ?` 绑定参数），排序仍为 `created_at DESC` |
| 离线测试 | `tests/test_cli_batches.py`，共 11 项 |
| 全量检查 | `python -m unittest discover -s tests -t .`：**104 项通过，0 失败** |

覆盖的行为：

| 场景 | 期望 | 结果 |
| --- | --- | --- |
| 省略 `--limit` | 列出全部批次，创建时间倒序 | 通过 |
| `--limit` 小于批次数 | 只返回最近 N 条 | 通过 |
| `--limit` 大于批次数 | 返回全部批次 | 通过 |
| 空库 | 提示「还没有批次」，退出码 0 | 通过 |
| `--limit` 为 0／负数／非整数 | CLI 拒绝（退出码 2），**不创建数据库或输出目录** | 通过 |
| 现有离线测试 | 继续通过 | 通过 |

该命令只读本地 SQLite，不访问采集站点，因此不需要新的真实站点验证项。
